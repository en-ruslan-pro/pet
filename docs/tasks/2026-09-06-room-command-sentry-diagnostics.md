# Диагностика ошибок команд комнаты

## Цель

Зафиксировать в Sentry контекст неудачной отправки команды управления питомцем,
чтобы по событию были видны действие, источник и связанные серверные записи.

## Ограничения и критерии готовности

- Не передавать код комнаты или имя питомца как диагностические данные.
- Сохранить исходное исключение и существующее поведение отката транзакции.
- Проверить обработку ошибки Feature-тестом Pest с `.env.testing`.

## Этапы

1. **Готово:** добавлен контекст Sentry перед повторным выбросом ошибки
   трансляции команды. Он содержит теги действия, источника и этапа, а также
   ID комнаты, персонажа и исполнения.
2. **Готово:** Feature-тест проверяет отправку контекста при ошибке Reverb;
   PHP отформатирован.

## Результат

- Изменены `RoomController`, сервис контекста Sentry и Feature-тест комнаты.
- Неудачная отправка теперь попадает в обычное событие Sentry с исходным
  исключением и стеком, дополненным данными `pet_command`.
- Не передаются код комнаты и имя питомца.
- Проверки: `vendor/bin/pest --compact tests/Feature/RoomTest.php` — 21 тест
  успешно; `vendor/bin/pint --dirty --format agent` — успешно;
  `git diff --check` — успешно.

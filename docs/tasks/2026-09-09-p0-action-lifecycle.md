# P0: контракт выполнения действий

## Цель и критерии

Завершить второй P0-подэтап MVP: одно TV-устройство подтверждает жизненный
цикл действия, сроки ожидания старта и выполнения рассчитываются отдельно из
снимка сценария, а доставка команды начинается только после сохранения
исполнения и может быть повторена.

## Этапы

1. Расширить сохранённый жизненный цикл действия сроками, TV-сеансом и статусом доставки.
2. Связать start/finish с TV-сеансом и отменять автономное действие при команде пользователя.
3. Добавить доставку после commit, повторную отправку и Pest-покрытие.

## Результат

1. **Готово:** исполнение хранит TV-сеанс, отдельные дедлайны старта и
   завершения, а также состояние и число попыток доставки команды.
2. **Готово:** первый TV-сеанс, начавший действие, становится единственным,
   кто может его завершить; команда пользователя отменяет незавершённое
   автономное действие.
3. **Готово:** команда доставляется после фиксации исполнения; при сбое остаётся
   в состоянии `pending` и повторяется ежеминутной командой планировщика.

## Изменённые области и проверки

- миграция жизненного цикла, модели исполнения и сервис телеметрии;
- контроллер комнаты, диспетчер и консольная повторная доставка;
- TV-клиент передаёт свой ID сеанса при start/finish;
- Pest-покрытие действий и телеметрии.

Проверки: preflight подтвердил SQLite in-memory из `.env.testing`; `vendor/bin/pest
tests/Feature/PetTelemetryTest.php tests/Feature/RoomTest.php` — 34 теста и 129
проверок успешно; `npm run build`, Pint, PHPStan и `git diff --check` успешно.

Остаются ручные сценарии с двумя реальными TV, перезапуском Reverb и потерей
